# Native tables and PDF hardening — 2026-10-01

## Changes

- Added native-only HAST table wrappers using the existing shared GFM/math parser. The extension's DOM extraction is not needed for local Markdown files; its default renderer output remains unchanged.
- Screen tables are semantic tables inside accessible, focusable horizontal scroll regions. Markdown left/center/right column alignment is honored.
- Print-only rules remove scrolling and UI overlays, clear mobile editor-mode hiding/viewport clipping, constrain tables to paper width, wrap text, repeat headers and paginate table rows. Dense tables use compact padding. No paper-size settings were added to Windows.
- Android no longer starts printing immediately before fonts/images settle. It uses native PrintAttributes as the sole paper/margin authority, retains true zero margins, rejects invalid/custom-size bounds, uses standard A4/Letter media IDs and requested orientation, and handles concurrent jobs and job cleanup through PrintDocumentAdapter.onFinish.
- Temporary Android styles and event listeners are removed on completion/cancellation/start failure. No screenshot PDF engine was introduced. Yas digits and all font preferences are unchanged.

## Verification limits

- A physical Android test exported all columns without scrollbars but exposed a native margin reset. The subsequent adapter fix compiled and was installed; final save-and-inspect verification was interrupted and remains incomplete.
- Latest Windows WebView2 native export verification remains incomplete. The reference PDFs were generated by Chromium, not the installed application's print flow. See `docs/VALIDATION.md` for release limitations.
- Very dense tables on small portrait paper may wrap within words; choose landscape/larger paper for greater readability. Tests do not establish correctness for every possible unbounded equation or unusually large individual table row.
